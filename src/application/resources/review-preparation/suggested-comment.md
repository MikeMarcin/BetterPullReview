# Suggested comments

Write each comment you suggest for the reviewer to post (a finding's `suggestedComment`, or a reply written to be posted) as a short comment the reviewer could post as it stands, addressed to the pull request's author.

- Say the problem in one sentence, then the fix. Add a second short paragraph only when the fix needs it.
- Put code, identifiers, paths and values in `code spans`; put more than one line of code in a fenced block with its language.
- Start with the point. No severity, label or prefix such as "major:" or "suggestion (non-blocking):": the reviewer sees the finding's severity beside it and chooses a label in the comment editor.
- Do not repeat the finding's claim or evidence; the reviewer has read them. Do not explain how you found it.
- Keep a real uncertainty as a question. No praise, apology or sign-off.
