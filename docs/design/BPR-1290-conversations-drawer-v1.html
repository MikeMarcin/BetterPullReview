None of this is implemented. All three candidates make the conversation the drawer. They differ only in how you pick a thread.

Common to all three

The conversationThe selected thread fills the drawer under one header row: where it is (click it, or the target icon, to show the line), then icons for Resolve, Mark read and More. Every post has its full body. There is no separate post list and no separate body pane.
PostsBPR-1083 v4, unchanged: an 18 px avatar, the 16 px mark 3 px under it, and the rail 3 px left of it in the label's tint. The rail is grey for a plain post. A blocking post has a filled mark and a 4 px rail. The body starts at the subject. Replies sit one step in.
NewA "New" rule above the first unread post, a blue dot by each unread author, and read authors in grey.
Depth, without the mapPosts are listed in order. A reply that answers anything other than the post above it shows a "↩ name: first words" chip, and clicking the chip goes to that post. A post that starts several branches has a ⑂ count, which folds and unfolds them. A folded run becomes one row, "7 more", with its people. The map and the "Path to this reply" caption are gone.
Reply in placeA one-line Reply field at the foot of the conversation. Focusing it opens the editor, with the label chip (⌘L), a note that it is kept as your draft, Discard and Publish. What goes inside the editor is BPR-1212's to settle, and this drawer takes whatever it decides.
DraftsA draft is dashed and marked "Only you", with Edit, Delete and Publish. Publish keeps its word because it publishes.
Scope and filtersTwo icons, This file and Whole pull request, plus a filter icon whose menu holds New, Unresolved, Drafts and Defects. Every icon has a tooltip.
RemovedThe "Conversations drawer" caption (the tabs are the header, as the specification says), the cards that repeated the posts, the thread map, the path caption, and the seven-line post list.

A. Switcher

One row of chips, one per thread on this file. Each chip shows the root's mark (or its author's avatar when the root has no label), the line, and the new count. Drafts are dashed. The list icon opens every thread, grouped by file. The conversation takes everything below the row.

B. Stack

Every thread is a one-line row: the root's mark, the line, the first words, who took part and the new count. The open thread expands in place to the full height between the rows above it and the rows below it, and its row carries the thread's actions. Scope and filters work the same way, and Whole pull request adds file headings.

C. Line rail

A 24 px strip down the drawer's left edge. Each thread is a tick at its line's height, next to the code, so it keeps the line alignment that RFC-BPR-0028 AC-05 asks for. The selected tick is ringed, and a tick's tooltip names the thread. Arrows step to the previous and next thread, and the list icon opens the same grouped list as A. The strip costs 24 px of width.
