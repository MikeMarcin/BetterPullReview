The Dressed report as an HTML template

The agent still writes the round 1 Markdown. The app turns it into a page in the hand of the attended-review pages: serif reading text on slate, colour spent only on verdicts, and one device for a verdict everywhere, a rule at the left. Each report is drawn twice: as a real HTML and CSS template, and within what the report tab can lay out today.

Owner, 2026-11-14, on round 1: “Dressed, possibly with an actual html template to render like how we do our attended review.”

  • The HTML template is template/report.css and the markup the app would produce from the Markdown. A browser engine draws it. The app has none: docs/architecture/system-architecture.md says “No Qt WebEngine”, and RFC-BPR-0001 and RFC-BPR-0036 say the same. Whether to add one is the owner’s decision; nothing here adds it.
  • Within today’s tab. The report tab lays its body out with Qt’s rich text (QTextDocument). The second frame of each report is not a drawing: it is that same report, written in the HTML subset Qt supports and laid out by Qt 6.11 itself, offscreen. The files are in qt/.
  • What Qt’s subset loses against the template: rounded corners, the 5 point meter’s rounding, real buttons inside the text (Add as draft comment is a link), the balance of the title’s lines, and hover. It keeps the type, the slate, the left rules, the washes on a suggestion, numbered code, aligned rows and the places at the right.
  • The floating ☰ and its popover are the app’s own widgets over the page in both cases, as built.
