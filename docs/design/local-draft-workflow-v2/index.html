Revise: a mode for the author, with the checklist first

Round 1 ended with the owner choosing B, the Workflow tab. He then said where the author's bench should live.

“I think I like workflow, it should become the first tab and become active when we enter that mode. It's very close to A but doesn't confuse the user by making status have different meanings across surfaces.”

“Sent back is too strong, maybe that happens, maybe i just decide to make a change, maybe there's just a light optional nitpick to handle. Publish update is better than Publish response.”

“Oh you know what. Maybe revise becomes a modality at the top that only shows up when you own the PR.”

This round reads “a modality at the top” as a fifth mode in the window's mode switcher, beside Overview, Review, Discuss and Threads. Mockups only. No product code changed.

Where Revise sits

Revise is the last mode in the switcher and takes ⌘5, so Overview, Review, Discuss and Threads keep ⌘1 to ⌘4. It is there only when the signed-in account opened the pull request, and for a local draft. On anyone else's pull request the switcher is the four modes it is today.

What the mode holds

Revise is the author's bench that was accepted on 2026-11-12, moved out of Review into a mode of its own. On the left is This update: the files that would go, picked as Uncommitted, Not pushed or Whole PR, with the commit box, and under them the conversations that are open. In the middle is the selected file. On the right the drawer opens on Workflow, the author's checklist, with the handoff at the right end of the bar. Review goes back to being for reading.

The Workflow tab, in three cases and four states

The tab holds round 1's list: a headline, then every step in small groups, the workflow's actions among them. A filled mark is something BetterPullReview saw itself; an outlined mark is something a companion reported.

Status keeps its one meaning

Status is Overview's tab and says what GitHub says, for an author as for anyone. Nothing about the workflow is added to it.

Recommended defaults

  • Position and key. Last in the switcher, ⌘5. Nothing renumbers, and nothing is missing from the middle when the mode is absent.
  • What opens in Revise. A local draft and a draft pull request I own open in Revise. An open pull request I own opens on Overview, as today, with Revise one key away. After that a window reopens in the mode it was left in.
  • What Revise remembers for each pull request. The comparison picked, the file, and the drawer tab. The first entry opens the drawer on Workflow.
  • Without a worktree. Revise is still in the switcher. Its page asks for the worktree once, and the rows that need one wait for it.
  • The handoff. Create Draft PR…, Ready for review and Publish update… sit at the right end of Revise's bar. Ready for review also stays on the title's line in Overview, where it is today.
  • A local draft's Status tab. Its publish steps move into Workflow, so a local draft has no Status tab until the pull request exists.
  • Review. The Edit view and the Local Changes tab leave Review for Revise.

What the application lacks today

  • A workflow belongs to a local draft. A pull request that never had one needs a worktree associated with it (RFC-BPR-0122, Proposed).
  • Publish update… is RFC-BPR-0124's Publish response… under the owner's name for it, and is Proposed. So are the conversation items of RFC-BPR-0122 and the agent's replies of RFC-BPR-0123.
  • The switcher has four fixed modes; a fifth that comes and goes is new.
