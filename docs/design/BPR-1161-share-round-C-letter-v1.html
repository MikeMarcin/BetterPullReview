Direction C: the round as a letter

BPR-1161, share-round design round v1, for RC61-05. Drawn on 2026-10-02 from the rejected candidate BPR-1161-compose-share-v001 (built at 7a385389c).

The share page stays a page, but it becomes the thing you are sending. The left shows the round the way its reader will meet it: what you ask, your note for the whole round, then each note with its code and suggested change, in order. A single panel on the right sends it.

The owner’s three complaints, answered

“There is a lot going on in this screen and it’s not a very pretty experience. I have no idea how I got to this screen, why I would wnat to do any of these actions, and what is important.”

How did I get here?
A labelled Share notes button with the count, as in direction A, opens the page. Its header names where you came from (the Back button reads “parser.cpp”), what this is (“Round 2”, not shared yet) and, in one line, what you are looking at: your notes since round 1, as their reader will see them. The file list and the Notes tray step aside, so the page shows nothing twice.
Why would I do each thing?
The left is only about what the round says, and every control there changes the text. The right is only about where it goes. Copy and Save each carry a one-line reason, and the panel’s foot says that sharing fixes the round as it reads on the left.
What’s important?
The letter is the largest thing on screen, because it is what you are sending. Copy round 2 is the only filled button. The digest, byte count and raw Markdown are behind Show the exact text at the letter’s foot.

What changes from the rejected page

  • The preview and the editing merge. The raw Markdown pane is replaced by a readable rendering of the same round: code excerpts and suggested changes drawn in the diff panes’ colours, not as SHA-256 values. The exact text is one disclosure away.
  • The page takes the whole width under the review bar instead of sitting between the file list and the tray.
  • Share buttons move from the top, where they came before the choices that shape what they send, to a panel beside the round.
  • Move Up and Move Down become drag handles with Option+Up and Option+Down. “Shared so far” is a short list in the panel, with its caveat under it.

Building it in Qt

The page replaces the comparison area below the review bar, as the rejected page did, so the navigation and Back/Escape behaviour carry over. The letter is a QScrollArea of note widgets; each code excerpt and suggested change reuses the existing code-sample painter (code_sample_painter.cpp), so syntax and diff colours match the panes. The side panel is a fixed-width column of ordinary push buttons. No window chrome changes.

What it costs

  • It is still a separate place: the code is hidden while you are on the page, and getting back is one click or Escape.
  • It is the most work of the three, because it draws every note’s code and change on the page.
  • For a round of one short note, a whole page is more than the job needs. Direction A suits that case better.
