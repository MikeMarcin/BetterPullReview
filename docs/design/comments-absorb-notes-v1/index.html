Comments absorb notes

One comment that is Local, Draft or Published, in place of comments and notes. Every window frame is the pull request window at 1280 by 800 with invented content, drawn with the accepted mock’s tokens and no new hue. The frames are live HTML; the linked renders are offscreen, light and dark.

The owner, 2026-11-12: “I think we should collapse comments and notes into just comments. Comments right now have published and draft states, this would just be adding a local state. Maybe there’s some minor complication with a local comment landing on the same row as a draft or published comment but I think we could deal and then I think we get to simplify a lot by dropping notes. You could demote a draft comment to a note / local comment so every place that asks both can just become draft.”

One comment, three states

A note becomes a comment that is Local. Nothing else about a note is lost: it can still sit on the pull request, on a whole file or on a line, and it still never leaves this computer. What changes is that it is the same object as a draft, in the same drawer, and one press moves it either way.

The same line, all three

The complication the owner expected. It goes away if a Local comment has exactly a draft’s two shapes: it is either about the thread (a Local reply, inside the thread’s card) or about the line (its own card in the line’s group). Make draft then never has to ask what to become.

  • Order in a card: published posts, then my Local replies, then my draft reply, then the reply field.
  • Any number of Local comments may share a line. Drafts keep today’s rule.
  • Local never counts as new, unread, open or resolved. The tab’s count and the label counters ignore it, as they ignore notes today.
  • It follows its thread: it collapses and goes outdated with it. If the thread is gone it becomes a Local comment at the thread’s last line and says so.
  • Outdated Local comments follow the placed ones with the sentence saying why. None is ever moved to a nearby line (today’s note rule, unchanged).

The composer

One composer writes all three. Where the foot says “Private until you publish” today there is a two-segment control. Comment…, the gutter and Reply open it on Draft. N opens it on Local. Choosing the other segment on a saved comment is Make draft or Keep local.

Finding them

Notes are in none of Threads, Overview’s Comments column or Finish your review today; drafts are in all three (BPR-2092 to BPR-2094). Local comments join them, and My drafts becomes a state filter.

One action where there were two

“Every place that asks both can just become draft.” Where no line can take a draft, the one action keeps it Local instead and says so.

Questions for the owner

  1. Its name. Default: Local, with the lock and “Only on this computer”.
  2. What a new comment starts as. Default: Draft from Comment…, the gutter and Reply; Local from N; not remembered.
  3. Make draft: move or copy. Default: move.
  4. Overview’s Note column and Private notes row. Default: retire both.
  5. Finish your review mentions Local. Default: one quiet line with Show.
  6. A Local reply inside a published thread. Default: yes.
  7. Agent opt-ins. Default: still two (local comments; drafts).
  8. Local PR drafts’ notes. Default: join in name and card only, last.
  9. Review Cycle notes. Default: out of scope.
  10. Draft file comments and pull-request comments from Local. Default: not in this RFC.
  11. Published key names (review_notes_not_selected, notes). Default: keep.
  12. A local draft’s comments follow to the pull request. Default: no.
  13. Insights’ Private notes tile. Default: rename to Local comments.
  14. How many share a line. Default: any number Local; drafts as today.
