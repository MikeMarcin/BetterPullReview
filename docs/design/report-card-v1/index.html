The agent’s report: its card and its tab

A long answer from the agent is a report. It is a card in the Agent drawer where it was asked, and it opens as a tab beside the files. This page draws what is built today and three ways to make both look better, each in both places, light and dark.

Owner, 2026-11-14: “I think we can make both the agent drawer report card and the file tab report card look a little better.”

  • Every frame is the window at its real size (1280 by 820 points, a 323 point drawer, a 631 point pane for the tab) in the application’s own colour roles.
  • The pull request is the fixture the owner looked at (#21, nested folders). The report is longer than the fixture agent’s, so each design carries a code block, a sub-heading and a list. All four designs show the same report.
  • The turn’s footer (who answered, Copy, Draft, Ask more) and the rest of the drawer are drawn as built in every frame. Only the report changes.
  • The tab’s Ask is drawn where the separate change puts it: a small control on the active file tab, and nothing on a report’s tab. The last section shows it against today’s strip.
  • A card and a tab can be chosen from different options. They are paired here by the idea they share.

Current: what is built

Drawn from agent_tab_view.cpp and agent_report_view.cpp and the owner’s two screenshots of 2026-11-14, so the options have something exact to stand beside.

A · Tidy: the same card, set properly

Nothing moves. The card keeps its title, counts, lead and Open report; the tab keeps its outline at the left and its body at the right. Every part is set with more care.

What it gives
  • The cheapest to build: the same widgets and the same layout, restyled.
  • Fixes what reads as unfinished without asking the reviewer to learn anything.
  • The outline is always in view.
What it costs
  • The page is still narrow: 455 points beside the rail in a default window, about 55 characters a line.
  • Two lists still stand side by side (the files’ tree, then the outline).
  • The card is still a teaser: it says a report exists, not what is in it.

B · Contents: the sections in the card, a jump bar in the tab

A report is its sections. The card lists them, each with its first words, and a row opens the report at that section. In the tab the outline leaves the pane for a jump bar, as Xcode and Finder’s path bar have, and the whole pane is the page.

What it gives
  • The card is useful before it is opened: it says what the report covers and goes straight to a part.
  • The page gets the whole pane: about 80 characters a line in a default window, and it stays readable when the drawer and the files’ tree are both open.
  • One list beside the files’ tree, not two.
  • The jump bar is one line however long the outline is.
What it costs
  • The tallest card: four rows here, up to six.
  • The outline in the tab is one press away, not in view, when the drawer shows another tab.
  • Open report is an icon in the card’s corner, not a labelled button.
  • New parts to build: the row list and the jump bar with its menu.

C · Attachment: a summary with the report attached; sections that fold

The chat stays a chat: the summary reads as any answer does, and the report rides under it as an attachment, the way Mail and Messages carry a file. The tab is the document, and its sections fold to their first sentence, so a long report opens as a digest.

What it gives
  • A long report is scannable at once: every section and its first sentence in one screen.
  • The shortest card, and the summary is not cut.
  • The page gets the whole pane, and the outline is the document itself, so it is never out of view.
What it costs
  • Reading straight through takes presses, or Expand all first. Which sections start open needs a rule (all, when the report fits the pane?).
  • The largest build: the body becomes one view a section, and find-in-report has to open what it finds in.
  • The card says least about what the report holds.

The tab’s Ask, moved

A separate change, drawn in every tab frame above so the options are judged on the strip they will live in. The Ask at the end of the strip becomes a small control on the active file tab. A report’s tab has none: the drawer’s composer asks about the report.

What any option fixes

  • The body stops at about 190 points. In the build the report’s body is a short box and the report scrolls inside it (second screenshot: it ends at “Merged main”). The page should run the pane’s height.
  • “4 section(s), 17 line(s)”. The counts need their plural forms. The first heading is the title, so it should not be counted as a section.
  • The lead keeps its Markdown. Backticks show, and the three lines are taken across headings, so a section’s sentence follows the summary. Each option shows the summary only (what stands before the first section), rendered.
  • The tab’s title is cut at its start. “…d since your review” loses the words that tell two reports apart.
  • The title is said four times with a report open: the tab, above the outline, in the outline, in the body.
