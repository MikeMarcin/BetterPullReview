The modes fold the way the drawer tabs do

Round 2 of the title row's fit. The owner chose icons when it gets narrow, "because we already do that for the drawer tabs", kept Ctrl+N on Windows, and asked for the same on all three platforms. So this is one design: the mode switcher takes the drawer tabs' faces, on macOS, Windows and Linux, and each platform keeps its own key while there is room for it.

Mockups to accept or reject. No product code changed. Every strip was drawn on its own platform by the application's own title row sources. The pull request, its branch and its titles are invented.

The faces, widest first

The first two are what the switcher shows today. The last two are the drawer tabs' own narrow faces: the open one keeps its glyph and name while the others show glyphs, then glyphs alone. As in the drawers, a mode shows no icon while its name is showing with the rest.

The row takes the widest face beside which the whole name fits: repository, number and title. When none does, the open mode keeps its name for as long as a title still fits beside it, and the last face is the icons alone. So the other modes' names yield before the title is cut, and the open mode's name yields before the title is lost. The room only shrinks as the window narrows, so nothing comes back at a narrower width.

The fold replaces the three-letter prefixes, the row's last yield today. With a fifth mode they no longer tell the modes apart: Review and Revise are both Rev.

The icons

Nothing is new art. Each is a glyph the application already draws beside the drawers, by the same painters, at the same 16 pixels and the same stroke as the tabs' and the strip's glyphs.

Notes for the build


    

  • A face is three properties of the segments the switcher already has: text, icon and tool-button style. The strip's style already draws an icon and a name with the tabs' four-pixel gap. Nothing in these renders is painted outside that style.
    • 

  • The face rule is the one in fit_tray_tabs and Overview's drawer. The switcher would be its third copy.
    • 

  • The current mode's glyph needs the highlighted-text ink, since it sits on the accent.
    • 

  • Two rules can go: the Windows-only threshold that drops the keys below 1300, and the rule that shows the title only if it would also fit beside the keyed switcher. The fold decides both from the room.
    • 




How these were made


A scratch program in harness/ compiles the lane's workbench_strip.cpp, conversation_glyphs.cpp, windows_caption_buttons.cpp, keyboard_shortcuts.cpp and three small dependencies unchanged, and builds the row from them with the fifth mode and the branch chip of the Revise design. It ran on each platform without showing a window.
