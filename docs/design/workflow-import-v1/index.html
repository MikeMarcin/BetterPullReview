The import preview, three options

Settings, Agents, Import… opens a configuration file and shows what it would bring before anything is saved. The owner rejected the window that ships today (look workflow-v002, 2026-11-15):

Why does this window look so different than everything else in the app? Why would leave out be the default? We’re trying to improt it? Why does it take so many actions to choose between those 3 options? Why is it so hard to read what it does? We need to send this window back for a front end design pass.

Three options follow, A, B and C. Nothing here is built. The file is the repository’s own fixture, “Synthetic Org pull request workflow”, with three things added so every state shows: an earlier revision of the workflow already on this computer, a prompt that is the same as yours, and a second workflow that names an action this version does not know.

What all three do

The four questions get the same answers in every option. The options differ in where the answers are put.

  • It looks like Settings. Grouped rows, a name at the left and its control at the right, the tags and segmented controls the Prompts page uses, the sheet an agent’s settings open in. No tree with column headers, no splitter, no table that cuts its words off.
  • Importing is the default. Everything the file can bring starts chosen: a new item is added, an updated one is updated. Import is enabled the moment the window opens.
  • One action per choice. The choices sit on the item, all visible, and one click picks one. Nothing is selected first and no pop-up is opened, with one exception drawn below: when several of your agents could stand for the file’s agent, the middle choice opens a menu of them.
  • Each item says what it does here. New, Updated or Unchanged; the revision that replaces yours; who runs each action and with what; and what each action says it does, in whole sentences that wrap.
  • RFC-BPR-0112’s rules hold. No program path travels: a program is named by the file and chosen here. An unknown action is named and its workflow refused. An update is compared with yours, with what it adds and what now does more marked, before Import is pressed, and drafts keep the earlier revision until the update is accepted there. Importing runs nothing. Build and run tests is the one thing a file can ask for that stays off until it is ticked.

A. One sheet

A sheet over Settings, as an agent’s settings are. Every item in the file is a group in one column, with its choice on its own row and what it does written under it. There is no selection and no second pane: what you read is all there is.

For
Nothing is hidden behind a selection. The default file, one workflow and its agent, reads top to bottom in one pass, and Import needs no click before it.
Against
It is tall. A file with many agents or prompts scrolls, and a prompt’s text has no room to be compared side by side here; a changed prompt would open its comparison under its row.
To build
Least. The preview’s decisions do not change; the tree, the splitter and the stacked detail pages become one scrolling column of the groups Settings already draws.

B. List and detail

The Prompt library’s shape in a sheet: a ticked list of the file’s items at the left, the selected one in full at the right. A tick is the choice to import. An update is shown as yours beside the file’s, row against row.

For
It holds a large file: twenty prompts are twenty short rows. The comparison has room, so an update shows yours and the file’s side by side.
Against
Only one item’s detail shows at a time, so reading everything means clicking through the list. An agent’s choice is in two places: the tick, then Add or Use in the detail.
To build
Middling. The same two panes as today, redrawn with the Prompt library’s list and Settings’ groups, plus the side-by-side action comparison.

C. In the page

No window at all. The file opens into the Agents page: a banner says what is being imported and holds Cancel and Import, and the file’s agent and workflow appear in the page’s own lists, where they will live, with a blue edge until they are saved.

For
It cannot look unlike Settings, because it is Settings. “Replaces yours” is seen on the row it replaces, beside the agents you already have.
Against
The page gains a mode: leaving it, searching settings or opening an agent mid-import all need an answer. Prompts live on another page, so the banner can only mention them. The workflow falls below the fold in a short window.
To build
Most. The Agents page must draw unsaved rows among saved ones and hold them until Import or Cancel.

Recommendation

A. It answers each of the four questions in the plainest way, it is the shape the app already uses for an agent’s settings, and it asks nothing of the reader but to read down and press Import. Take B’s yours-beside-the-file’s comparison later if large files turn out to be common. C is the most at home in Settings and the most to build.
