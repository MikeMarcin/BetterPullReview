Home says whose move each of my pull requests is

RFC-DRAFT-0001

We need “returned to me” as a status for my PRs on Home … or it can go back into Needs me or My pull requests, but it would need a clear reason attached so I can tell that someone is waiting on me or the PR is ready to merge.

My pull requests already holds exactly the authored pull requests that are not waiting on a reviewer. What it lacks is the reason. Each row there now leads with one word for the next move and a sentence that names who and what: Returned when a reviewer handed it back, Ready when it can merge, Failing when checks block it. Returned rows sort first and take the Needs me tone, because they are the same kind of debt.

Settled 2026-11-10: reasons inside My pull requests, the frame on the left. The section on the right is kept here as the alternative that was not chosen.

The Tour tab keeps publishing and the agent in reach

RFC-DRAFT-0002 (layout), RFC-DRAFT-0009 (stops), RFC-DRAFT-0003 (Enhance, references)

Tour publish shouldn't be hidden away at the bottom. Tour model picker should stay pinned at the bottom, not be off screen when there are many stops. Drafted tour stop references to code … can these become real links or snippets instead of saying something like (lines N-M). … Going to a tour stop should go to the code by default, right now it's an extra click. … there feels like too many options outside of edit mode still. … Ready-next is awkward. … Accept still has value, and we already have a visual language for that for the files in the PR review. … The yellow/green ring is good.

Today the whole tab is one scrolling column, so both the publish button and the agent bar leave the screen once the route is long. The tab becomes three bands: a head that states where the tour stands and carries the one publish action, the route that scrolls, and the agent bar that stays at the bottom as it does in the Agent tab.

In a stop's text, a file and line is a link that reveals those lines in Review, and a reference on a line of its own opens as a snippet. On GitHub the same reference becomes a commit-pinned permalink.

Arriving at a stop, by any route, shows its lines in Review; Show in code goes away, and the stop's file-and-lines line is the way back if you scrolled off. A stop at rest is for reading and going: Edit and its chat. Everything that changes it lives in the edit state.

You accept a stop the way you accept a file. The ring is green when what you accepted is what the stop is now, and yellow when the stop is new or something under it changed: its lines, or lines its text links to. A yellow stop shows why and offers Accept; a green one offers nothing. The ring itself only shows the state and opens the stop, as now. Ready, next and Suggest an outline are gone.

Publishing reports each step and chooses its own form

RFC-DRAFT-0002

Should at least give progress updates as it's doing multi-part publishes. Errors like “route doesn't support” are hard to tell they're even important. And if we know what the route does or doesn't support why don't we just pick the right one?

The three-way mode list goes away. The plan picks the least fragmented form that carries every stop and says so in one sentence, with the stops that forced it. The list of steps becomes a checklist that advances as GitHub accepts each write. A failure is a banner in the error role with the step that failed, what is and is not on GitHub, and the action that recovers.

The tour side chat ends in a composer and one quiet line

RFC-DRAFT-0003, RFC-DRAFT-0004 (cost, send key)

The tour side chat window UX got made ugly, especially at the bottom. I feel like the little blue text that says apply chat to the code is sufficient. … the whole tour right now … always takes one turn to tell it what I want and a second turn to apply it. … Agent tab shows agent spend cost at the bottom after a turn ends, tour should too.

Six things stack under the transcript today. The permanent Update button duplicates the blue link, and the session rows describe the normal case. After the change the transcript is followed by the composer and one line: the session on the left, what it has cost on the right. Continuation and revision notices appear only when something is not normal.

A request to change the tour is answered with the change in the same turn, as a proposal you accept in the chat. The blue link stays for the case where the agent only talked, in every thread rather than only the tour's.

The Agent tab shows what it sends and that work is happening

RFC-DRAFT-0005 (context), RFC-DRAFT-0006 (activity), RFC-DRAFT-0007 (scratch), RFC-DRAFT-0004 (links, cost, keys)

“Review this pull request” errors with “Not sent. Select the lines to ask about in the diff, then send.” … The whole “what this agent may read” field is confusing to me. … One request responded with “I've started three parallel reviewers” but there is no UX to view background or sub-agents or their progress, so I have no idea if the agent is running or stalled.

The scope list goes. The agent can read the whole pull request whatever it says, and in the code that list changes nothing that is sent. In its place the composer shows the one thing that does differ between questions: the lines you are pointing at. Select lines and they attach as a chip; remove the chip or press Escape in the diff and the question is about the pull request. A suggestion carries its own subject, so Review this pull request never asks for a selection.

While a turn runs, the tab says what the agent is doing, when it last did anything, and which helpers it started. A turn is not finished while helpers are still working. Quiet for two minutes is said out loud.

Settled 2026-11-10: the scratch folder starts on, its starting state is a setting on each agent, and a change you make in a pull request is remembered for that pull request.

Settled 2026-11-10: “build and run tests” is part of 0.5.0. It is off until you turn it on for an agent, works only in the disposable checkout, and asks once per pull request.

The tour on Overview reads like the tour

RFC-DRAFT-0002

We need to fix the tour UX on overview.

The note does not say what is wrong. This frame fixes what the code shows to be rough, and you confirmed those are the faults you meant: Problem and Solution are written as Markdown but drawn as plain text, a stop is a bare title with nowhere to go, and an author sees no publication state or publish action. Stops gain their file and first sentence and open that stop in Review; the state line and its action match the Tour tab's head.

Settled 2026-11-10: these three fixes are what the note meant.

The agent accent means this starts an agent run

RFC-DRAFT-0004

We should probably maintain that indigo means agentic feature on buttons throughout the app, aka agent tab too. Things that don't cost money and are purely mechanical stay the normal colors.

One test decides the colour of a control: does pressing it start or continue an agent run? If so it wears the agent accent, everywhere. If it only moves, keeps, discards or shows something, it uses the ordinary button roles, even when what it handles came from an agent. The Agent tab wears no accent today; several Accept buttons in the tour do.

Settled 2026-11-10: the accent is a colour you can change per theme on Appearance › Colours. Indigo, as drawn here, is its default.
