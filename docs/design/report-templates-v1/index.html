Report templates

A template for each report the app asks an agent for, and the system prompt that asks for it. Each report here is the same Markdown in both directions. A is that Markdown shown as Markdown. B is the same text with the app drawing what the template lets it recognise.

Owner, 2026-11-14: “the report is ugly as crap. Like we need maybe a system prompt and a template to fit the reports in.”

  • One convention for all five: a title, one summary paragraph (the card shows it), fixed section headings for the kind, then items under them. An item is a third-level heading, the line it is about on the next line, then why. The ☰ list is the headings.
  • The agent writes Markdown, not JSON. The headings the app navigates by are the ones the reader sees, a report that strays from the template still reads, and Copy source stays readable. The two machine blocks the app already reads at the end of an answer (bpr-claims, bpr-findings) stay as they are.
  • A, Markdown only. The prompt and the template do all the work. The app shows the report as it shows any Markdown: nothing new to build beyond the prompts.
  • B, dressed. The app reads the template: verdict words become badges with a tally under the summary and on the card, an item’s line sits at the right of its heading, code carries its line numbers, a suggestion is a diff with Add as draft comment, and list rows line up.
  • Every frame is the report tab’s page (572 point column, the floating ☰) beside the card in the Agent drawer. Each page is drawn whole; in the app it scrolls. The reports are parsed from examples/ by the convention’s own rules.
