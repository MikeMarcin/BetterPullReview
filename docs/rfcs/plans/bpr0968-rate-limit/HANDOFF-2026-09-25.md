## Implemented behavior

The profile runtime shares a bounded admission registry among every PR window,
keyed by canonical host, viewer node and API resource. All PR provider
submissions, including transient retries, consult it. Primary exhaustion uses
the later of Retry-After and primary reset; secondary uses Retry-After. Missing
minimums use 60/120/240/480/900 seconds. The fallback is capped; an explicit
server minimum is never shortened. Time arithmetic saturates and displayed
remaining seconds round up. The pure core receives explicit monotonic/wall
samples; host code owns clocks, synchronization and effects.

Rate failures schedule zero automatic retries. After expiry the user explicitly
opens or refreshes. Existing transient errors retain at most three attempts and
recheck the shared gate. Cooldown survives session replacement and cannot be
shortened by older success. It stores no delayed work or credentials. At 256
live records unknown keys fail closed; only expired records are evicted, and
late overflow preserves the longer minimum. Existing request identity rejects
cancelled or stale terminals; closing a window cancels the actual in-flight read.

application admission and window host, profile composition, test-only fixture
