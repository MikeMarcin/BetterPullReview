## Before and after

The workbench specification's bounded-navigation description currently says
a bounded press sends no gesture and changes nothing. Refine that description:
an active PR's file/change action also enters Review, even at a bound, while
the source navigation remains a no-op with its existing message. Both directions
share the new entry behavior. Keep the always-enabled arrows, exact keys,
three-second status, no-wrap rule and editable-input exceptions from BPR-1328.
Extend the specification's modality-entry description accordingly.

BPR-0924's fourth acceptance result and the first-PR plan's
[thread-reading integration evidence](../../plans/rfc-bpr-0037-first-pr-workflow/milestone-thread-reading-integration-evidence.md)
record Previous/Next change preserving Discuss while moving retained code.
Replace that runtime expectation for explicit file/change commands with Review
entry, retaining conversation identity and unsent work for return. RFC-BPR-0037's
thread-reading, PR-wide Discuss and explicit publication obligations remain;
this follow-up does not withdraw its AC-07 or AC-09 or reopen the done card.

Preserve BPR-1132's exact per-tab pair and reading-state contract and BPR-1295's
remembered Review arrangement. Extend their entry paths rather than applying
the explicit Review-button preset on each navigation. Update owning UX and
navigation/tab architecture documentation during implementation.
