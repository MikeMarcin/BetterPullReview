# Recover without making the situation worse

| CLI result | Response |
|---|---|
| target_ambiguous | Present the returned choices; obtain the author's exact profile/PR/root. |
| stale_revision / conflict | Retain the proposed text; reread current content and show the conflict. Do not force a newer revision onto the old edit. |
| editor_busy | Explain that an active editor/IME has uncommitted input; wait for the author to finish, without forcing commit or starting another store writer. |
| owner_protocol_unsupported | Name the required CLI/desktop compatibility. Do not open SQLite directly or steal the runtime lock. |
| context_export_refused | Keep manual authoring available. Do not relabel this agent as approved or retrieve the same content through another tool to evade policy. |
| interaction_required | Give the next normal human action, especially terminal publication. No simulated approval. |
| uncertain / partial | Run read-only recover for the returned attempt/request. Keep confirmed IDs; do not repost comments. |
| authentication_required | Explain the admitted connect action; invoke it only after an explicit user setup request. Do not extract tokens, change global gh auth or start a browser from ordinary reads. |
| missing CLI or incompatible schema | State the dependency/version issue. Do not install arbitrary software or create another publisher. |
| partial GitHub recovery | Explain which shared material is unavailable. Do not claim there are no stops or infer private context. |

Local drafts and undo history do not automatically exist on another machine. A pending GitHub review may expose staged bytes to its author, but is not a complete WIP copy or a recovered publish grant. A published tour recovers from ordinary GitHub comments and its index; missing private notes/provenance remain unknown.
