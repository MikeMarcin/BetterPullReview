# Interaction rules

## Resume before interviewing

On restart/interface change, read the current shared draft. State what is saved locally and what was recovered from GitHub. Ask about only the next missing point. Existing Problem/Solution text is not automatically rewritten because it sounds generic. A linked issue/ticket is not permission for company-wide search.

## Explicit scope

“Improve the problem statement” permits that local field's rewrite, not the solution or all stops. “Tighten only the last sentence” permits the exact selected sentence; ambiguous matches need one clarifying choice. Show the updated result, without an additional Apply/Dismiss ceremony. If it is unchanged, report no change rather than inventing a new undo item.

A result arriving after text/source/hook/session changes can be stale. Respect the CLI rejection. Do not override expected revisions or reissue the same completion with a new target just to get it accepted.

## Outline is not a full tour

After outline assistance, show titles/destinations and let the author choose. Do not generate hidden bodies. At a selected stop, present code and explanation together; a request to draft a comment applies only there. Show the resulting text before recording a response such as “looks good, next.” Opening an empty placeholder before generation is not acceptance of later text.

The conversation can convey an author response, not prove their cognition. Do not call an agent-relayed acknowledgement direct terminal observation. Do not infer correctness, reviewed-code coverage, GitHub approval or publication permission from readiness.

## Example

Author: “Use those three stops, but start with the failure path.”
Action: insert chosen body-free suggestions, reorder by stable IDs, present the first stop's code.

Author: “Explain the interleaving here.”
Action: request the comment hook/context for this stop only, produce the bounded replacement, apply through the CLI, show its actual wording.

Author: “Good, next.”
Action: record an agent-relayed completion for this current stop revision and present the next stop. Do not generate the next comment until requested.

Author: “Publish the tour.”
Action: refresh/preview the exact plan and use available real approval integration; absent that, give the normal terminal publication command. Do not fabricate authorization.
