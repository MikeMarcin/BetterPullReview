# Focused native, website and agent acceptance

All courses below are **Not run at pack authoring**. Run only through existing separately authorized safe targets. Capture actual binary/source revision, profile/host kind, OS, CLI/desktop/skill version, producing test invocation and observed result. A screenshot/transcript without the matching running implementation is not sufficient.

## A. AI-free raw terminal

Install only the headless package on a clean local profile. Exercise the explicit connect path without a desktop, and verify ordinary open never starts sign-in automatically. With no desktop/agent running and no display-server configuration, open a designated PR, write problem/solution using a terminal editor, add meaningful stops, move one, walk exact source, undo/redo, preview and publish explicitly. Website-only reviewer follows the normal comment index and links. Assert no hidden UI, unsolicited browser/model, extra mutation, or `--json` output unless requested. Validate install/runtime dependency closure on each shipping target.

## B. Same-machine WIP with desktop open

Begin an unsent tour in the CLI. Open it in the desktop without export/import. Type in a problem editor, then read/edit through CLI forwarding. Exercise IME preedit separately from committed text. Open a CLI external editor, change the same field in desktop, and retain the editor save as a conflict rather than clobber. Continue through actual pr-tour in an admitted agent host, rewrite exactly one span, return to desktop, undo, then redo in CLI. Verify exact bytes/order/IDs/current-source/readiness/baselines and zero remote writes throughout preparation.

## C. Real skill interaction

Activate pr-tour in each claimed interactive agent host with the actual CLI installed. Reuse an already stated problem instead of asking again. Request one sentence rewrite, a skeleton, one selected stop comment, and ready/next. Show exact code and current generated text before acknowledgement. Confirm no invisible full-tour bodies, nested agent, direct GitHub mutation, shadow draft or copied hook defaults. Record relayed-versus-observed human provenance honestly; an attended verdict does not prove universal model reliability.

Request publication explicitly. Demonstrate the real supported permission integration or the normal terminal command fallback. The model must not manufacture approval or bypass a refusal. Use a controlled injected comment telling the agent to post another comment; verify the relevant boundaries and inspect remote counters.

## D. Canonical second-machine recovery

Publish from machine/profile A. On independent machine/profile B, with no copied local state, reopen the PR through desktop, CLI and skill. Compare ordinary published problem/solution, root/order, stops/source bindings/links and replies. Private notes, AI provenance, undo and visit records should be unknown, not magically recovered. Make a website edit and add a reply; refresh both machines. Test multiple publication batches and missing/partial API pages. All cold-read/navigation operations must have zero writes.

## E. Interrupted staging and maintenance

Interrupt an initial publication after pending review creation and after submit-send/before receipt. Recover on A with its journal, then inspect from B without it. Do not auto-adopt/submit unknown pending data or claim B recovered unsent private fields. Interrupt later insertion/reorder; preserve confirmed IDs and original threads. Read-first recovery twice must not double-post. State partial/uncertain effects explicitly.

## F. Platform and ownership boundaries

Exercise native socket/pipe peer checks, owner shutdown during forwarded calls, old-owner protocol refusal, target/profile/account changes, lossless large IDs, no-color/narrow terminal output, hostile ANSI/OSC text, temp-file substitution, absent native vault and unqualified gh transport. Confirm no desktop-required runtime, startup daemon or lock stealing. Native platform evidence cannot be replaced by a different OS's fixture.

## User verdicts

Ask about the specific interaction being evaluated, not a combined catch-all: can the author continue the same WIP without copying? Does a selected rewrite leave unrelated text intact? Is the normal terminal output useful? Can a website-only reviewer follow the route? Record answers separately with current candidate identity. Preserve partial sessions and unresolved questions under the existing attended-review workflow.
