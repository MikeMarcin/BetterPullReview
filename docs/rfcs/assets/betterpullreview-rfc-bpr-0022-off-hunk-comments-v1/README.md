# BetterPullReview RFC-BPR-0022 pack

This import-ready pack proposes **RFC-BPR-0022: Semantic Source-Line Comments
and Off-Hunk Publication Compatibility**.

It is a new post-pack RFC. It does not edit, replace, or reopen
RFC-BPR-0008. Instead, it depends on RFC-BPR-0008 and extends its existing
review-publication seam so a reviewer can comment on any current-head line in
a file already changed by the pull request. BetterPullReview uses a native
line review comment when the connected GitHub host accepts one and otherwise
publishes an ordinary file-level review comment containing an immutable code
permalink. The presentation remains one semantic source-line comment.

## Pack contents

- `docs/rfcs/future/RFC-BPR-0022-semantic-source-line-comments-off-hunk-publication.md`
  — the normative RFC.
- `docs/rfcs/plans/RFC-BPR-0022-issue-plan.md` — the immutable planning
  snapshot and issue graph.
- `docs/verification/RFC-BPR-0022-verification-plan.md` — acceptance-focused
  verification ledger template.
- `cards/` — fifteen provisional issue-card templates. Allocate live IDs on
  import; do not preserve the provisional identifiers as repository issue IDs.
- `references/CURRENT-SOURCE-ALLOCATION.md` — exact live-tree seams this RFC
  extends.
- `references/EXTERNAL-AUTHORITY.md` — official GitHub facts and links captured
  for the design.
- `references/DECISION-LOG.md` — the product and architecture decisions made in
  the design discussion.
- `references/INDEX-ENTRY.md` — the proposed post-pack index row and explanatory
  text.
- `prompts/IMPLEMENT-RFC.md` — a ready-to-use implementation prompt.
- `scripts/validate_pack.py` — validates file inventory, digests, LF endings,
  provisional-card identity, and dependency references.

`IMPLEMENTATION-ORDER.md` is pack-only guidance. Per BetterPullReview's pack
lifecycle, do not import it as a second mutable tracker; encode the order in
live issue dependencies.

## Validate before import

```sh
python3 scripts/validate_pack.py
```

The validator is location-independent and may be run from any working

## Import into BetterPullReview

Import on `main` under the project-integrator lease:

1. Read the live `AGENTS.md`, `CONTRIBUTING.md`, current RFC index, issue-board
   rules, and `.agents/skills/implement-rfc/references/pack-lifecycle.md`.
2. Reconcile this pack against the live tree. The source snapshot used here was
   generated on 2026-09-04; live repository state wins.
3. Retain an exact copy of this directory under
   `docs/rfcs/assets/betterpullreview-rfc-bpr-0022-off-hunk-comments-v1/` and
   write the adjacent `LIVE_IMPORT` record from
   `references/LIVE-IMPORT.md.template`.
4. Copy the RFC to `docs/rfcs/future/`, the issue plan to
   `docs/rfcs/plans/`, and the verification plan to `docs/verification/`.
5. Add the post-pack row from `references/INDEX-ENTRY.md` to
   `docs/rfcs/README.md`. Do not insert RFC-BPR-0022 into the canonical
   fourteen-RFC pack-v2 sequence.
6. Allocate fifteen collision-free issue IDs with the live allocator. Rewrite
   each card filename, front matter, dependencies, links, plan table, and
   closeout references together. The current source snapshot had `BPR-0556` as
   the next unallocated ID, but that fact is deliberately not authoritative at
   import time.
7. Put cards in truthful board lanes. Most begin in `10-backlog/` until their
   dependencies are satisfied; the live-service card belongs in `40-parked/`
   only after all automated prerequisites are done and it is waiting solely on
   a designated GitHub/GHES interaction.
8. Set the closeout card's `RFC base:` to the full live Git commit containing
   the imported RFC and card graph.
9. Run `python3 scripts/verify_documentation.py --root .` and
   `git diff --check`, then commit the RFC, cards, ID allocation, index update,
   retained pack, and `LIVE_IMPORT` record together.
