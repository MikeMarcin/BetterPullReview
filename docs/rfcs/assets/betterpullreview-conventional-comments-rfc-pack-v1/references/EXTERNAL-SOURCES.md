# External contracts checked at authoring

Checked 2026-09-23 America/Los_Angeles. These sources inform interoperability;
new BPR behavior remains the proposal in the five RFCs. Do not fetch these pages
at application runtime or treat their current examples as the configured GHES
API version. No private project information was sought on the public web.

| Key | Primary source | Supported point |
| --- | --- | --- |
| CC | https://conventionalcomments.org/ | Twelve suggested labels, one-label prefix format, optional comma-separated decorations and optional discussion; standard decorations and label meanings. |
| GH-REVIEWS | https://docs.github.com/en/pull-requests/reference/pull-request-reviews | Comment, Approve and Request changes are native review-level choices. |
| GH-COMMENTS | https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/commenting-on-a-pull-request | Native review comments, suggested changes and conversation resolution coexist. |
| GH-APPLY | https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/incorporating-feedback-in-your-pull-request | Eligible native suggestions can be applied individually or as a batch; application creates a commit. |
| GH-WRITE-COMMENTS | https://docs.github.com/en/rest/pulls/comments | Raw Markdown bodies, review-comment create/update identity and line/range placement are API concerns distinct from our textual labels. |
| GH-WRITE-REVIEWS | https://docs.github.com/en/rest/pulls/reviews | Native review event submission remains the provider's review operation. |
