# End-to-end and attended courses

These are product acceptance procedures, **not run** in this archive. Use disposable
synthetic material and the established native verification recorder. A person can use
the fixture topic, but must exercise actual BPR output rather than copying this pack's
pre-generated example and claiming the product exported it.

## A. Defining agent-free course

Install the package whose manifest/dependency graph omits all agent adapters/helpers.
Use a clean profile with no provider or GitHub account. Open a module with preexisting
uncommitted changes, inspect full source and add eight connected items across four files.
Use an exact small replacement and an illustrative small replacement; preserve one
CRLF/tab file. Add a private scratch note that will not be shared.

Share the eight items as one readable Markdown file and as clipboard text. Confirm
no model/executable discovery and no network action occurred, and the scratch note is
absent. A human without BPR reads the document, makes the coherent requested source
changes in their normal tools and returns them. Capture R1 in BPR without a reply JSON
or completion event. Compare R0/R1, inspect full source including unchanged locations,
verify only work actually checked, and create a second round. Restart and repeat.

Record input source hashes, exact exported canonical identity, actual native gestures,
clipboard/file outcome distinction and complete revision/round history. Repeat with
automation separately absent. Nothing except direct retrieval/delivery convenience
may be missing. This is the first complete feature slice, not a late fallback test.

## B. External harness without embedded integration

Keep agent adapters absent but install the permitted AI-free CLI. Finish a round in
desktop. From an already running allowed harness, use the current bpr-cycle skill or
ordinary commands to read the exact frozen round. Check completeness/digest and all
items before implementation; verify no second model is started. Switch desktop tabs
and run another session to ensure no target leakage. Deny the scope and verify refusal.

Have the recipient make changes with its own tools. Test both a readable response and
a separately authorized structured response. Capture the next revision even when the
response import is omitted, interrupted or unavailable. Do not infer model/effort or
identity from a self-reported field. Measure user steering turns and context-preparation
work without promising model quality or savings.

## C. Optional direct delivery parity

Only after A and B, install an admitted direct adapter. Send the same frozen content
through an explicit profile/session, checking payload equivalence and context limits.
Distinguish send acceptance, acknowledgment, completion and uncertainty. Inject wrong
round/late output. Cancel or remove the adapter mid-cycle and continue manually. A
source update or read acknowledgment never verifies feedback or auto-publishes a PR.

## D. Clean PR publication

Use a separately authorized disposable repository/account/host. Start with initial
dirty work, module-only review scope, unrelated changes elsewhere and two local review
iterations. Prepare selected final content against an explicit parent/target. Inspect
both initial and iteration contributions and the actual final candidate diff. Verify
no omitted path is deleted and the user's index, branch and files remain unchanged.

Preview commit authorship, exact destination/new branch, title/body and selected public
content. Execute the approved native publication path, verify returned object/ref/PR
identity and server head/base, and exercise read-first interrupted recovery. Repeat
supported host/version cases with capability refusal where unavailable. Link the PR and
reopen original local rounds/revisions after the squash. Do not upload private history
or publish a Tour automatically. External preparation/linking is tested separately and
must not substitute for this native course.

## E. Native presentation and owner review

Exercise real target-native Windows/macOS/Linux builds within current supported gates.
Use RFC-0052's title/review bar/folding Updates/document tabs/right tray design; measure
platform width floors, selected pair restoration, stale completions, focus and reserved
shortcuts. Test IME, per-line irregular selections, virtual space, multi-caret clipboard
and undo in the actual suggestion editor. The prototype/spec does not constitute owner
acceptance; preserve the attended outcome and any unanswered decisions explicitly.

## F. Performance and benefit report

Name hardware, OS, build SHA, corpus size, warm/cold state and measured operations.
Record UI interaction p50/p95, capture/freeze/export/compare latency, memory and limits
on a 1M-LOC / 100k-file synthetic or authorized corpus. Compare the fixed eight-item
exercise with manual prompting: preparation time, human steering turns, omitted
requirements and rework. Keep recipient capability/settings stable and disclose small
sample/noise. Report mixed or negative results; one batch is not proof of lower tokens,
better code or fewer implementation mistakes.
