## Implementation

The desktop workflow records preview and admission before any provider exists.
The application host records discovery, Publish/Resume, factory construction,
recovery and terminals, including an early factory refusal. The production
session records each finite read/write operation and local journal, credential,
request, baseline and verification stages. All pre-write exits retain a typed
stage: authority, plan validation, recovery availability, lease, configuration,
binding, journal read, credential scope, identity check, request preparation,
baseline read or journal save. Factory errors retain their original failure
category. A post-effect malformed terminal remains unknown rather than becoming
a definite failure.

These are ordinary Standard `tour.operation` lines, admitted by the existing
logger and diagnostic export classifier. Their fields are closed stage/state/
failure vocabulary, a bounded HTTP status and a full SHA-256 authority-plus-key
attempt label. No key, name, URL, path, body, response, credential or source bytes
are recorded. Anonymized exports remap the local attempt digest with their fresh
namespace, preserving correlation within that export; identifying export keeps
the local digest. Invalid extra prose and invalid status/identity shapes are
rejected by the same classified grammar. Per-wire write flags distinguish sent
or possibly transmitted mutation attempts from refused dispatch; a write flag
never establishes publication success. Conversation replies retain their own
existing diagnostic family.

The UI names the failed operation and safe reason/status, supplies a next step,
and retains the draft. A new pre-write refusal says this attempt sent nothing;
it does not deny earlier staged/published work. A pre-provider Resume failure
retains the original staged prefix and still permits explicit Resume after a new
preview. Prior unknown outcomes remain unknown. The local preparation preview
now directs the author to the authoritative publication preview instead of
claiming that absent preparation-host observations prove missing qualification.
The proposal-complete notice refers to the list’s current readiness, so it does
not keep asking an already-ready author to repeat confirmation.

Only the three finite staged list operations adopt the existing 3 MiB /
32,768-value list budgets; the ten-page, 100-entry, exact-identity and continuation
checks remain. Their aggregate is bounded at 30 MiB. Single-object response,
request, source, actor/head, durable witness, one-use child grant, tests-on
safety and no-blind-retry rules remain. No review-author prohibition was bypassed:
valid author compatibility publication already uses ordinary PR comments, and
description updating is still separate.
