## Explicit limits and policy

Fully disconnected startup has no accepted `/user` identity and exposes no
authenticated Recent or cache content. A stored credential, Recent row, Git object
or overview is never substituted for account authority. Extending this is a product
policy decision outside this mandate; no new offline identity policy is proposed.

Source reads support only an exact match to the latest available retained epoch,
UTF-8 text without NUL, and at most 256 KiB per endpoint. An older cached pair,
missing/retired/rehydration-required material, binary/non-UTF8 or excessive source
remains explicitly unavailable/unsupported. Source is exact base/head text, not a
recomputed provider or merge-base diff. Historical conversation anchors and links
remain inert; current participant/check/progress/permission data is unavailable.
Persistence may lag an accepted read while one save is in flight; freshness is
always unknown. Windows/Linux and human/native GUI evidence remain unverified.

No explicit human criterion is attached to this card. These limits are recorded
under AC3's requirement to retain unsupported cases. No new attended session,
server, push or release is authorized or created.
