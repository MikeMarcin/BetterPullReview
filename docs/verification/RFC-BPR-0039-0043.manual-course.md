## Single manual course

1. With AI unconfigured, open the designated draft PR. Confirm the accepted
   host/account, head and draft status. Use **Prepare review tour**. Manually write
   Problem and Solution, select two exact code ranges, and use **Add tour stop**.
   Write titles/explanations, move the second stop before the first, revisit both
   fields, and inspect the raw Markdown preview. Record the ordered destinations.
2. Prepare publication. Inspect the captured owner/head, exact range/body per
   stop, representation limits and separate description choice. Before transmission
   confirm the supported operation rows. Submit the explicit plan as COMMENT;
   never use APPROVE or REQUEST_CHANGES for this course. Record actual review,
   comment and root IDs/URLs, submitted event, and preserved draft status.
3. In a browser with only the reviewer account, start at the overview, follow the
   first stop, Next/Previous/overview links and exact code permalinks, and leave an
   ordinary reply. Inspect every stop without BPR. Record observed visibility of
   pending versus submitted comments separately; do not assume pending editability.
4. With the author account on the website, edit one stop's narrative, the Solution
   section and an unrelated description template paragraph. Reopen BPR and confirm
   the exact website versions. For a separate overlap case, retain a local Problem
   edit while changing that same website section, refresh, inspect B/L/R, restart,
   and explicitly choose one version. Check that unrelated template bytes survive.
5. Reorder existing stops, prepare an update and check that its bodies/index are
   the only changed objects. Publish and confirm that original comment IDs and the
   reviewer's reply remain. Reopening/refreshing alone must produce no writes.
6. Add a third stop and move it into the middle. Start the explicit update and use
   Stop after a confirmed new destination. Record precisely which operations
   completed. Restart, reconcile by reads, inspect the partial website tour and
   its overview escape links, then explicitly Resume. Confirm no duplicate
   creation/submission and that the root update is last.
7. Explicitly retarget one stop. Confirm a new linked destination and a preserved
   old discussion/source. Remove a replied-to stop from membership and confirm the
   shared original and reply remain accessible. Do not delete reviewer content.
8. Advance or force-push only the designated test branch under its separate
   authorization. Select a retained original-to-current comparison. Exercise moved,
   renamed, changed, identical-but-context-changed and unavailable sources. Inspect
   original versus proposed range, deliberate reaffirmation, and absence of any
   automatic public reanchoring or review-state change.
9. Close BPR and admit a fresh isolated profile. Open the same PR, explicitly select
   its original root in import choices, and verify current website brief, ordered
   IDs and exact raw bodies across batches. Confirm unknown private history and no
   inferred preparation/AI provenance. Preview without editing: no normalization
   writes. Navigate and reply from the website again.

For every boundary, capture counts independently from the client journal using
server-returned identities and a before/after inventory. Record creations, body
edits and COMMENT submissions separately. Capture the root, stop and reply IDs
and exact synthetic bodies; no successful write should be inferred from a UI
message alone. Failed/ambiguous requests retain their actual effects and desired
text. The fixture's expected counts are not a mandated live-server count.

## Native attended criteria

On each eligible native build, present one criterion per attended-review item:

- Keyboard focus and route navigation remain usable after reorder and conflict.
- Native IME composition, Unicode, multiline clipboard and text Undo preserve text.
- Screen-reader names and conflict versions distinguish baseline, local and website.
- Ordinary and large route layouts remain usable at required sizes/scales.
- Large bounded-route edit/navigation timings and memory remain within recorded limits.

Use the configured attended-review companion when the candidate and native
station are ready. Keep-or-change questions use Accept/Reject with notes. Bind
screenshots, objective measurements and verdicts to the exact build; a fixture
capture does not satisfy these native judgments.
