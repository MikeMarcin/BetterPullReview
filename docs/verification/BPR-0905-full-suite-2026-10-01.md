## What each station returns

The criterion is the four rows. A red row elsewhere in the suite is recorded
but does not fail BPR-0905 unless it is a clock failure that the rule should
have caught. Each station returns:

1. `HEAD`, the product-path diff against `4c3205c09` (expected empty), core
   count, and load at the start and end of the run.
2. The total rows, passed, failed, and the `Total Test time (real)`.
3. For each of the four rows: the result, the row time, and every
   `PUBLIC_PATH_BUDGET` line for the three application rows. Expected: all
   four pass, every line has `expired=0`, and the row times are well inside
   660 / 660 / 500 / 420 s.
4. Each failing row with its one-line headline, and whether it is a clock
   failure (`RUN_BUDGET_EXPIRED`, `PROCESS_TIMEOUT` or `***Timeout`).
5. That platform's margin table, built from the `json-v1` inventory and the
   run log the same way as the Mac table above: every passing row whose
   explicit `TIMEOUT` is less than three times its duration in this run, with
   its timeout, duration and ratio, plus the count of rows with an explicit
   `TIMEOUT`. This is the native inventory the survey still lacks.
