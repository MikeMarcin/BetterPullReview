Option 1 - assert the decoded content and canonical structure, not the compressed bytes

Replace `data == encode_png(decode_png_bytes(data))` with a check on what the file decodes to: the committed PNG's decompressed filtered scanlines must equal the scanlines the generator produces, and its chunk structure must be canonical. Byte equality of the DEFLATE stream stops being asserted. This is the option the card's own analysis favours, and the measurement below is what makes the trade-off exact rather than argued.

Acceptance criteria

  • A hand-edited sprite still fails the canon - measured, not assumed
  • The canon holds on an interpreter linked against either zlib or zlib-ng
  • The property the canon asserts is stated rather than implied

Known concerns

  • A re-compression that changes no pixel and no filter choice is accepted where it is rejected today. That is the entire behavioural difference, and it is the case nobody was defending against.
  • The canon stops proving 'your DEFLATE implementation matches mine'. If that property is wanted for some other reason, this option loses it.

Measurement

A deliberately altered pixel
One channel of one pixel in dif-neutral-master.png changed by 17, then re-encoded into a structurally valid canonical PNG that passes every existing structural check. The replacement REJECTS it. Measured, which is this card's second required bullet.
A recompression that changes nothing visible
The identical filtered scanlines recompressed at level 6: 746,919 bytes against the committed 745,543. The replacement ACCEPTS it; byte equality rejects it. This one case is byte equality's entire marginal coverage.
What the structural check already covers
decode_png_bytes already rejects any chunk that is not IHDR, IDAT or IEND, any bad CRC, non-consecutive IDATs, anything that is not non-interlaced 8-bit RGBA, and any decompressed size that disagrees with the header. None of that is being given up.
Committed tree today
One IDAT chunk; scanlines equal the generator's own filtering; byte equality passes on this host, whose interpreter links zlib 1.2.12.

Option 2 - keep byte equality and pin the compressor

Keep asserting the exact compressed bytes, and make them reproducible by vendoring a deterministic DEFLATE implementation or by storing each asset's expected IDAT stream alongside it.

Acceptance criteria

  • Byte equality survives an interpreter change
  • The added dependency or the second copy of every compressed stream is an accepted cost

Known concerns

  • A vendored DEFLATE is a new build-time dependency in a tool that currently has none beyond the standard library.
  • Storing expected IDAT streams doubles the compressed bytes in the repository for every asset and adds a second thing that can drift.
  • It keeps a property whose only demonstrated effect is rejecting a recompression that changes no pixel.
