Do not build anonymous public preview

RFC-BPR-0017 stays Deferred, BPR-0312 stays unresolved, and every implementation card (BPR-0300 through BPR-0317) stays dependency-blocked. The device-authorization flow (RFC-BPR-0016, shipped on macOS since BPR-0318) is the answer to reading a pull request without a stored token, as the RFC itself recommends when the rate budget is not workable.

Mechanical audit: PASS — All five probe captures validate (VALID:5, BOUND:5) at their owning commits.

Details and identity

Acceptance criteria

  • The mode is not wanted under the measured limits; the decision is recorded as evidence on BPR-0299.

Known concerns

  • Public repositories still require sign-in; RFC-0016's device flow is enabled only on macOS so far (Windows and Linux flips are BPR-0311 and BPR-0310).

Measured facts (docs/verification/reviews/rfc0017-anonymous-probe-v001)

  • Unauthenticated REST core budget: x-ratelimit-limit 60 per hour per source address, shared by every client behind that address; opening one pull request costs several requests.
  • A conditional GET answered 304 Not Modified consumed one core unit (used 3 -> 4), so refresh is not exempt.
  • GraphQL refuses anonymous callers with 403 and x-ratelimit-limit 0, so the workbench's review-thread selection has no anonymous route.
  • REST pull-request review comments answered 200 anonymously (per_page=1 course), so source-anchored comments could be recovered through a new read operation nobody has carded.
  • A private or missing repository answers 404, so the mode cannot distinguish absent from private.
  • GHES in private mode rejects all unauthenticated access; the mode would be GitHub.com-only.
