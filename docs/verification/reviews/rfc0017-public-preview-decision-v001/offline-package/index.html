Acceptance criteria

  • The four definitions below are what the RFC-BPR-0017 implementation cards must build, in these words.
  • The mode stays read-only, triage-less, GitHub.com-only, and credential-free; nothing here grants mutation, private read, or a second read path.

Known concerns

  • The budget is shared by every client behind one source address, so the ring can move without this operator doing anything; the tooltip has to read as a shared budget rather than a personal one.
  • A read-path REST review-comment operation and its fixtures are still uncarded, so “no review threads” is the shipped behavior until one exists.
  • Windows device authorization is not verified yet (BPR-0311), so the sign-in handoff stays hidden there while the preview itself runs.

Proposed definitions to bind

Public-preview name
“Public preview”, with “signed out” stated beside it wherever the mode is named — the profile selector, the window title, and the workbench header all read “Public preview — signed out”. It is never presented as the authenticated workbench with fields missing.
Limit presentation
Not a persistent bar. A small ring indicator in the workbench fills as the shared hourly core budget is consumed, in the manner of Claude Desktop’s usage ring. Hovering it shows a tooltip carrying the consumed fraction and the reset time — “32% of the hourly limit · Resets in 3 hr 4 min” — and, in that same tooltip, what the preview cannot do: GitHub.com only, no review threads, no triage or publishing. A conditional request answered 304 spends one unit like any other, so the ring moves on refresh. Budget exhaustion is a typed refusal naming the limit and the reset time, never a network or authentication error.
Sign-in handoff
The RFC-BPR-0016 device authorization flow is offered from the ring’s tooltip and from every refusal — budget exhausted, review threads unavailable, and any triage or publishing attempt — and returns to the same pull request after sign-in.
Supported-platform policy
All three desktop platforms — macOS, Linux, and Windows x64 — because the preview needs no credential store. GitHub.com public repositories only; every GHES profile stays unavailable and sends zero requests. The sign-in handoff is shown only where device authorization is enabled on that platform: macOS and Linux today, since BPR-0310 is terminal, and Windows once BPR-0311 — now ready on the Windows lane — is terminal too.

Measured facts the definitions rest on

  • Unauthenticated REST core budget: 60 requests per hour per source address, shared by every client behind that address; opening one pull request costs several.
  • A conditional GET answered 304 Not Modified consumed one core unit (used 3 → 4), so refresh is not exempt.
  • GraphQL refuses anonymous callers with 403 and x-ratelimit-limit 0, so review threads have no anonymous route.
  • REST pull-request review comments answered 200 anonymously, but no read-path operation calls that source today.
  • A private or missing repository answers 404, so the mode cannot distinguish absent from private.
  • GHES in private mode rejects all unauthenticated access, so the mode is GitHub.com-only.
