Keep comment bodies in the drawer and use a source-margin marker?

BPR-0414 implements exact drawer-to-code navigation and exact code-line-to-drawer filtering. In the production GitHub path, a current right-side root is placeable only after the response head identity matches the accepted head; unsafe, outdated, file-level, or incomplete anchors remain unplaced rather than guessed. Selecting this drawer thread reveals right-side line 42 through the existing semantic line-selection path. The remaining choice is where the prose belongs. Accept means the code view stays a natural source document with the narrow marker and selected-line band as its conversation indication while the root and replies remain readable in the drawer. Reject means that boundary is insufficient and the comment body should be designed into the code view, which conflicts with RFC-BPR-0005's current no-inline-row rule and therefore needs explicit successor scope.

Acceptance criteria

  • The selected drawer thread is unmistakably associated with right-side line 42
  • The root and reply remain readable without inserting prose into the source document
  • The narrow margin marker plus ordinary selected-line band is enough confirmation after navigation
  • Keeping natural source layout uninterrupted is the right tradeoff for the shipped drawer

Known concerns

  • The 4 px margin marker is intentionally restrained and may be too subtle without the selected-line band
  • A wide conversations drawer reduces the comparison width, especially on compact windows
  • The screenshot uses a synthetic fixture thread and offscreen QFusionStyle rather than live content and target-native styling
  • Production currently fails closed for LEFT anchors because the provider cannot prove the GitHub merge-base coordinate matches the accepted base-tip pane
  • Outdated, file-level, and otherwise unsafe anchors remain visibly in the drawer with a reason but receive no guessed code marker; those states are covered by tests, not this image
  • The drawer in this capture differs from the one reviewed in the withdrawn batch ab6145717475dfdfddd6206d: BPR-0418 added the thread map above the thread, so the thread itself now occupies less of the drawer. That is deliberately visible here rather than cropped out, because it is the drawer that ships.
