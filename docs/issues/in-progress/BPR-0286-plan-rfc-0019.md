# Plan RFC-BPR-0019 implementation and verification

Establish the immutable run anchor, asset ownership boundaries, complete issue
graph, documentation ledger, attended checkpoints, and final-head verification
matrix before any Dif production asset enters the repository.

## Run anchor

- RFC base: `58b5116f8706ac336664cc3fc39dabc66745a70d`
- Requested set and order: RFC-BPR-0019, then RFC-BPR-0020.
- Product-owner direction: the 2026-08-12 instruction to design the mascot RFCs
  and then implement them advances the post-pack implementation frontier for
  this ordered set.
- Non-waived gates: that direction is not an ownership/license assertion, an
  attended visual verdict, an RFC-BPR-0006/RFC-BPR-0013 closeout, or authority
  to consume Nib, Mel, or AllTheThings identity.

## Planning requirements

- Allocate separate authority/provenance, deterministic tooling, original
  source art, generated-contract testing, attended visual review, isolation,
  documentation, simplification, and ordinary closeout slices.
- Keep owned sources and generated products below the Qt adapter asset root,
  but keep the offline generator and validator outside the runtime resource
  authority.
- Make the ordinary developer, core-only, and tests-disabled application
  graphs consume no generator and require no art-generation dependency.
- Bind the rights and visual decisions to exact reference, source, manifest,
  generator, generated-product, and preview hashes.
- Stop before RFC-BPR-0020 unless RFC-BPR-0019 is genuinely Auto-Verified.
