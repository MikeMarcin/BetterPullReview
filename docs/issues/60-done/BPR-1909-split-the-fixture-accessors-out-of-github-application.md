# Split the fixture accessors out of github_application.cpp

Round 5 of the `github_application.cpp` refactor. The root still holds
14,400 lines of tests-only `github_application_fixture_access` members: the
composition courses' drivers and evidence readers, with 77 anonymous helpers.

## Acceptance

- AC1: Move the accessors, unchanged, into tests-only course files under
  `src/app/src/github_application/`, one per course family; helpers used by
  one file stay private to it, and the few used by several are declared in
  shared fixture-support headers.
- AC2: Every moved definition stays under `BPR_BUILD_TESTING`, so a tests-off
  build compiles none of it.
- AC3: Preserve behavior: full dev and tests-off builds; the composition
  contracts (source and Release), round-trip and every course whose driver
  moved; format and documentation gates.
- AC4: Land the change, the completed card and a journal line on local main.

## Result

Source `ea6d91228` (regenerated byte-identically over main `02e657325`, which rebased round 4 and landed BPR-1914, BPR-1915 and BPR-1918); `github_application.cpp` goes from 17,481 to 3,161 lines.
Course files (lines): `fixture_reply_and_draft_courses.cpp` 1779, `fixture_uiforetw_capture.cpp` 1556, `fixture_label_authoring_course.cpp` 1545, `fixture_start_review_course.cpp` 1529, `fixture_threaded_reply_course.cpp` 1305, `fixture_uiforetw_course.cpp` 1227, `fixture_appearance_course.cpp` 872, `fixture_review_round_trip_course.cpp` 850, `fixture_course_modality.cpp` 816, `fixture_effect_holds_and_agent_evidence.cpp` 806, `fixture_review_ledger_course.cpp` 754, `fixture_defect_course.cpp` 743, `fixture_workbench_course.cpp` 677, `fixture_uiforetw_observation.cpp` 413, `fixture_start_and_evidence.cpp` 398, `fixture_uiforetw_observation.hpp` 194, `fixture_course_support.hpp` 88, `fixture_course_support.cpp` 36.

Each file is one course family and stays under the 2,000-line ceiling. Helpers
used by a single course stay private to it; `fixture_course_support` (course
phases, waits, drawer rows) and `fixture_uiforetw_observation` (the UIforETW
review's blob identities and the intraline, role and navigation observations
its course and capture share) declare the rest. Two deduced-return JSON
helpers stay `inline` in that header because their bodies must be visible
where they are called. The startup accessors stay in the root beside the
startup implementation they construct, until that moves next.

Generation now also counts the complete types that member access and implicit
derived-to-base conversions need, uses of helpers named only inside generic
lambdas, and overloads together; the UIforETW capture adds glaze and
`terminal_diagnostics.hpp`, which it uses only inside templates.

Checks on macOS arm64: full dev build; tests-off composition build;
clang-format 22; and a 360-row integration pass over every `application_*`,
`qt_composed_*`, architecture and live-mutation row: 348 pass. Of the 12:
`application_profile_window_review_restoration_public_path` timed out under
`-j4` and passes alone; six `application_large_review_*` rows are Debug
timing benchmarks, nongating by the owner's standing instruction; and
`application_agent_invocation_composition_contract`,
`application_review_tour_publication_manual`,
`application_threaded_reply_contract`, `application_thread_words_public_path`,
`application_accepted_file_in_overview` and
`application_pending_states_public_path` fail identically at round 1
(`2fc1cb2a3`), before this refactor. Windows and Linux were not built.

Over main's BPR-1914/1915/1918 edits to the window files, the combined tree
builds in both configurations and passes 67 of 69 composition, round-trip,
tour, agent and architecture rows; the two failures are the pre-existing ones
above.
