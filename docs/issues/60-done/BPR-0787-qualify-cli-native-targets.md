# Qualify the CLI connector on target-native platforms

- [x] Mac tests-disabled read and fixture write show the selected installed CLI, actual account warning, process cleanup and terminal behavior.
- [x] Redirect, Unix socket/config, CA, account-switch, executable and descendant/PID risks are probed and described without a false containment claim.
- [x] Windows and Linux remain explicitly unavailable until each platform has its own native credential, process, read/write and UI evidence.
- [x] Documentation and verification retain actual versions, limitations and safe-test boundaries without credentials or private repository content.

Mac qualification at product source `4c4eb408`: the tests-disabled release app's read consent named the configured-CLI risks and separate publication authority. Its selected fixture profile showed `octo-reviewer`, loaded `octo-org/review-repository#17`, and rendered the exact earlier 11–16/later 21–26 `review.cpp` comparison with `Diff ready — 1 semantic changes`. The same app with the installed `gh` also displayed its actual observed `MikeMarcin` identity on `github.com` after consent. The d4 held synthetic review and inline POSTs, separate write warnings, server receipts and success-specific inline terminal are retained in `build/rfc0015-r2-d4-publication-evidence.json`. All task-owned UI processes exited or were reaped. The development `.app` passed local code-signature verification but Gatekeeper refused it as a distributable; no signed/notarized package was claimed.

A bounded native read-only probe used official `gh` 2.100.0 and Apple Git 2.50.1 (Apple Git-155) on macOS 26.6.2 arm64. The selected account reported a keyring token source, a matching Keychain generic-password item existed, and an exact-commit HTTPS clone of a small owner-controlled private repository invoked `gh auth git-credential get`. Git reached the exact head; observed temporary use was 16,046 bytes/15 entries, the store was removed, and CLI config metadata and executable digest were unchanged. The private name, objects, response bodies and token were not retained. This supports one helper-backed read, not precise Security API tracing, credential-generation binding, strict disk quota, or an application private-PR render. A separate public clone did not invoke the helper. The legacy migration and symlink/write-denial probes are in `build/rfc0015-r2-d3-gh-clone-containment.json`; the bounded d5 records are `build/rfc0015-r2-d5-private-helper-evidence.json`, `build/rfc0015-r2-d5-native-gh-evidence.json`, `build/rfc0015-r2-d5-ui-evidence.json` and `build/rfc0015-r2-d5-package-path.json` (all ignored, no sensitive content).

The historical 2.95/2.96 socket/302 probes remain failures of strict containment. The current 2.100.0 local trust probe failed an old exact-origin assertion at redirect characterization, so it supplies no passing redirect result. Socket/config/CA and executable replacement, account switching and escaped descendants/PID reuse remain disclosed, uncontained trust risks. Windows and Linux are explicitly unavailable pending target-native gates. [The verification ledger](../../verification/RFC-BPR-0015.md) records the distinction and preserves the safe-target boundary: no live PR mutation occurred.
