# The review fixture reads as code, not as a list

Asked for by the product owner after rejecting the `selection_contrast_remedy`
batch: the captures could not be judged because the panes did not look like a
code comparison.

BPR-0196 owns the larger half of that — the panes paint none of the diff. The
two are complementary rather than ordered: this card changes what the lines
say, BPR-0196 changes how they are painted, and neither waits on the other.
This card owns the half the owner asked about directly: the content itself is
`prefix-20`, `old-a`, `middle-b-7`. Single tokens, one per line, no structure.
Even painted perfectly, that reads as a list because it *is* a list.

## The second reason nothing could ever be coloured

The fixture's file is named **`review.txt`**.

`packaged_syntax_classifier` selects a definition by path. A `.txt` path selects
plain text, so once BPR-0185 links the classifier, this fixture would still
render every token in one colour and the linkage would look broken. The rename
is not cosmetic; it is a precondition for syntax highlighting ever being visible
on the surface every attended review uses.

## What must be preserved

The fixture's *shape* is load-bearing and stays exactly as it is:

| Region | Lines | Role |
|---|---|---|
| long first line | 1 | horizontal-extent case |
| common prefix | 28 | |
| base 4 → head 7 | 4 / 7 | **replacement** |
| common middle A | 12 | |
| base only | 4 | **deletion** |
| common middle B | 12 | |
| head only | 5 | **insertion** |
| common tail | 50 | |

Base 111 lines, `head_one` 115, `head_two` 116 with its force-push marker.
Three semantic changes. Substituting code line-for-line keeps every structural
assertion — group counts, spans, the "3 semantic changes" text — while changing
only what the lines say.

## Regeneration is derived, never hand-edited

The manifest pins commit, tree, and blob OIDs, pack byte lengths, and pack
SHA-256 digests; the packs themselves are frozen base64 in
`github_public_path_fixture.cpp`. All of it is derived from the content, so all
of it is regenerated by the recipe in the fixture's own README — hash-object,
mktree, commit-tree with the recorded identity and timestamps, then
`pack-objects --revs`.

Do not hand-edit an OID to make something pass. `tests/scripts/verify_epoch_history_fixture.py`
regenerates the graph independently and compares; a hand-edited digest fails it,
which is the point of it existing.

## An attempt was made and reverted

The content, the git graph, the packs, and the manifest were all regenerated by
the README's recipe, and `epoch_history_fixture_contract` passed against them —
so the regeneration itself is sound and reproducible.

It was reverted because the `--diff-workbench-probe` course then failed while
the plain fixture path still passed. That probe drives `reveal_segment` against
named alignment segments and compares projected document positions, so it pins
something about the old content's geometry beyond the line counts this card
preserved. Finding exactly what is the remaining work here.

Nothing was committed. Start from the recipe again rather than from a patch.

## Required direct evidence

- `verify_epoch_history_fixture.py` passes against the regenerated manifest and
  the frozen packs.
- Base is 111 lines, `head_one` 115, `head_two` 116, and the workbench still
  reports three semantic changes.
- The file's path selects a real syntax definition rather than plain text,
  asserted against `packaged_definition_catalog` rather than by reading the
  extension.
- A capture of the composed surface shows code, and is attached to the next
  attended batch rather than described.
- The full `dev` and `core-only` suites pass, because the fixture drives the
  epoch, diff, and public-path courses.
